# Corrupt language packs

Committed on purpose, and regenerated by the block at the top of `tools/`'s corpus generator
whenever the format changes.

Each file is wrong in one named way, so a failure points at the check that stopped caring rather
than at "something was malformed". Several have their checksums repaired after being damaged:
without that the CRC rejects them first and the section-bounds arithmetic behind it is never
reached — which is the code that actually does pointer arithmetic over a file a user was given.

`pack_corpus_test` loads every one of these and, for any that survive validation, queries the
engine through them and reads every byte of every suggestion it returns. Refusing bad input is
half the requirement; the other half is that input which *passes* validation and is structurally
nonsense must still not walk off the end of anything.
