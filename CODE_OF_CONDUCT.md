# Code of conduct

This applies wherever the project is discussed: issues, pull requests, reviews, discussions,
the forum threads the maintainers take part in, and any private message sent because of the
project.

## The standard

- Be civil. Disagree with the code, the measurement or the decision, not with the person.
- Be specific. A report that says what happened, on which build, is worth more than an
  opinion about the whole project; a review that names the line is worth more than one that
  names the author.
- Assume competence and good faith until shown otherwise, and say plainly when you were wrong.
- Keep other people's text private. The project exists so that what someone types stays on
  their phone; screenshots, logs and clipboard contents posted in an issue must be the
  reporter's own, and anything that looks like somebody else's is removed.
- No harassment, no slurs, no sexualised remarks, no threats, no doxxing, and no persistent
  contact with someone who has asked you to stop. None of this is a matter of tone.

## Enforcement

The maintainers decide what falls under this document. A first breach gets a warning and, where
something was posted, an edit or a removal. A second, or a serious first, gets a block from the
project's spaces on GitHub. A block can be appealed once, in writing, to the maintainers, who
answer within thirty days.

Report a breach by e-mail to the address on the maintainer's GitHub profile, or, if the
maintainer is the problem, through GitHub's own reporting. Reports are read by the maintainers
only and are not published.
